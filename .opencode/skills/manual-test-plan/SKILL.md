# План проверки

Словарь: поверхность, роль, приоритет P0–P2, стенд, сборка. Один пункт — одно наблюдаемое ожидание.

## Настройки

1. Прочитай `./qa.config.yaml`. Если файла нет, прочитай `~/.config/opencode/qa.config.yaml`.
2. Если обоих нет, остановись и перечисли ключи из `qa.config.example.yaml` (в этом репозитории он лежит в `.opencode/qa.config.example.yaml`).
3. Возьми `active`. Если `projects.<active>` нет, остановись.
4. Обязателен непустой `task.acceptance`. Без него план не пиши: остановись и попроси критерий.
5. `project.root` и ветки нужны для P2. Если `task.branch` или `project.base_branch` пусты либо ветки нет локально, выпусти только P0 и P1 и явно напиши, что P2 не построен.
6. Если `task.stand` или `task.role` заданы, сверь их со списками проекта.
7. URL стенда не открывай. Не вызывай curl, wget, HTTP-клиенты, скрипты и браузер на стенд. Не делай `git fetch`.

## Что сделать

1. P0 — счастливый путь критерия приёмки, та роль, что в `task.role`.
2. P1 — права, границы, пустые и ошибочные состояния, смена состояния, если это следует из критерия или diff.
3. Если в диалоге уже есть карта влияния по этой ветке, возьми её для P2. Иначе при живых локальных ветках сам выполни `git -C "<root>" diff "<base_branch>...<task.branch>"` и выдели соседние поверхности. Это не заменяет полный разбор change-impact.
4. Для каждого id из `project.surfaces` прочитай один файл `references/<id>.md` рядом с этим SKILL.md. Добавляй оттуда только пункты, которые относятся к этой задаче. Неизвестный id пропусти и назови его в ответе. Пустой список surfaces — справочники не читай.
5. Держи весь план в пределах 8–15 пунктов. Не добивай число пустыми проверками. Если критерий узкий и пунктов меньше, напиши почему.
6. Где сценарий ещё неясен, пометь короткую исследовательскую сессию вместо пошагового кейса.
7. Ожидание формулируй так, чтобы человек увидел его на стенде. Сам стенд не проверяй.

Не заводи дефекты и не пиши итог прогона.

## Ответ

```markdown
# План проверки <task.id>

Стенд: <id, не открывался>
Роль: <role или «не задана»>
Сборка: <build или «не задана»>

## P0
1. Предусловие: ...
   Действие: ...
   Ожидание: ...
   Роль: ...

## P1
...

## P2
...

## Исследовательски
- <сессия и зачем>

## Не проверять в этой задаче
- ...

## Почему пунктов меньше 8
<только если так вышло>
```
