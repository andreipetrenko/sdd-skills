# Итог в задачу

Словарь: стенд, сборка, роль, вердикт. Вердикт — ровно одна строка из `project.verdicts`.

## Настройки

1. Прочитай `./qa.config.yaml`. Если файла нет, прочитай `~/.config/opencode/qa.config.yaml`.
2. Если обоих нет, остановись и перечисли ключи из `qa.config.example.yaml` (в этом репозитории он лежит в `.opencode/qa.config.example.yaml`).
3. Возьми `active`. Если `projects.<active>` нет, остановись.
4. Обязательны непустые `task.id`, `task.notes`, `task.verdict`. Пустые заметки — остановка. Не пиши, что проверка прошла.
5. `task.verdict` должна совпадать с элементом `project.verdicts`. Иначе остановись и покажи список.
6. Если `task.stand` задан, он должен быть среди стендов проекта. Если `project.roles` не пуст и `task.role` задана, роль должна быть в списке.
7. URL стенда не открывай. Не вызывай curl, wget, HTTP-клиенты, скрипты и браузер.

## Что сделать

1. Разложи `task.notes` на три списка: что проверено, какие дефекты названы, что не смотрели и почему.
2. Пункт, которого нет в заметках, не переноси в «проверено». Фразу «в целом работает» не используй.
3. Если в диалоге есть план проверки этой задачи, ссылайся на его пункты. План заново не раздувай.
4. Остаточный риск пиши только по непроверенному из заметок и по дырам, которые в заметках названы.
5. Вердикт скопируй из конфига дословно.

Не подменяй пустой прогон удачным вердиктом.

## Ответ

```markdown
# Итог <task.id>

Стенд: <id или «не задан»>
Сборка: <build или «не задана»>
Роль: <role или «не задана»>
Вердикт: <ровно одна строка из project.verdicts>

## Проверено
- ...

## Дефекты
- ...

## Не проверялось
- <что> — <почему, из заметок>

## Остаточный риск
- ...
```
